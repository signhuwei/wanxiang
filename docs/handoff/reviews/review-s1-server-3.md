## 尚未关闭的联调问题

1. **默认管理员可见“查看正文”的入口，点开必然 404。** 默认合约，用 admin 查另一成员的 `/observe/sessions`，实测对象 `actions:["read"]`，对应 `/events` 为 404。`server/web/ledger.js:125-145` 把 `read` 解释成允许打开，`observation.js:48-62` 打开时立即拉正文。后端正确拒绝；问题在于“能读摘要”和“能读正文”没有区分。建议为**该对象**返回独立正文动作，UI 不向仅有摘要权限者提供该入口，同时保留本人可读。复验：同一 admin 的本人会话与他人会话应显示不同入口，owner 授正文后再可钻取。
2. **阅读区费用冻结在打开瞬间（静态确认，未量浏览器延迟）。** 打开活动会话后保持阅读区不动，再产生 usage。`observation.js:51-54` 仅用初始行 `s` 创建费用文字；`:79-81` 收摘要后重读正文和台账，但没有更新已打开的费用节点。会话台账与阅读区因此可显示不同数字；同时 `pending_usage_count` 未用于阅读区提示。请让阅读区使用更新后的会话计量数据。复验需在真实 API 页面不重新打开、不手动刷新，将新的 token、费用及待结算标记与数据库对照，并记录可见延迟；当前不签收 ≤5 s。
