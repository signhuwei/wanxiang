# 能力合约重构 · 模块功能设计

**模块设计 · 2026-11-21**　依据[《能力合约与条款库设计 v1》](capability-contract.md)。已确认的界面对应[《能力合约 v2》](../../contracts/capability-policy-v2.md)的数据结构与接口。本稿中原首版的兼容建议留作历史背景。

平台为每个租户签发一份**平台合约**，写明购买的席位、模型和其他权益，以及哪些条款允许租户调整。户主通过**租户配置**决定这些权益在组织内怎样使用。比如平台签发 50 席和模型 A、B，户主可以只启用 A、为研发组设月配额。增加第 51 席或取得模型 C，须经平台变更合约。

**橡皮是 OneX 的交易代币，当前 1 块橡皮对应人民币 1 元。** 租户购买橡皮后按块消费，数量可以是小数。合约分别标明代币购买价（元/块）和模型服务费率（块/百万 token），便于以后调价时说清哪项价格发生了变化。

充值数量、余额、月配额、租约额度、用量和账单都按块输入或显示。字段或表头标明单位，例如“月配额（块）”。现有账本和协议每 1,000 毫橡皮对应 1 块。页面保留有效小数至 0.001 块，编辑数量时若无法精确换算为整数毫橡皮，应提示可用精度。[通用单位约定](../../contracts/README.md)

## 1. 现状与改动

当前户主在“租户合约”同一张表单里填写席位数、Agent、模型 ID、租约时长与额度、监察可见范围，并可按系统和架构固定 Agent 发行。每次保存都会新增一版合约。平台开通时填过的席位数，后续可以被户主写入的新版本替换。已有按设备平台查询生效模型、费率和发行的入口，可以继续用于验证配置结果。[现有表单](../../server/web/contract.js) · [服务端读写](../../server/src/tenant-management.ts) · [现行 HTTP 契约](../../contracts/http-api.md)

现有充值表单已支持按块输入小数。合约租约额度和平台费率表单仍直接使用毫橡皮，组及成员配额对超出精度的输入会取整。开发验收时，这些入口均应遵循上面的块数和精度约定。[充值](../../server/web/billing.js) · [租户合约](../../server/web/contract.js) · [平台费率](../../server/web/catalog.js) · [配额换算](../../server/web/format.js)

| 业务项 | 平台合约决定什么 | 租户可以做什么 | 生效位置 |
| --- | --- | --- | --- |
| 席位 | 签约席位上限 | 查看上限、已占和可用数，邀请、停用和重新启用成员。建议首期只保留一个席位上限 | 新增、重新启用、接受邀请时按活跃成员数检查 |
| 模型、Agent、发行 | 授权目录、可用 Agent、允许的版本范围或平台锁定的发行 | 从候选项中勾选启用范围；允许固定版本时，为每个 Agent、系统、架构选择一项 | 成员入口、发行下载、设备配置、启动和模型请求 |
| 路由与自有上游 | 允许的协议、主备策略、能否自配模型或接自有 Provider | 获准后在本租户登记上游、选择模型和路由顺序。自有模型须归入本租户获准的目录 | Server 按有效路由选择密钥，Edge 在本机执行 |
| 橡皮与配额 | 签约套餐、费率或议价、租约的时长与额度边界、是否允许组和个人分配 | 查看费率和用量，在开放范围内调低租约上限、分配月度配额 | 实时报价、租约签发与续租、账本结算 |
| 治理 | 监察、留存、导出等条款的可调范围和强制要求 | 户主在边界内授权管理员和组管查看摘要或正文，设置开放的治理项 | Server 读取、导出及审计；Edge 执行已支持的设备策略 |

## 2. 模块与操作入口

| 模块 | 操作者与主要操作 | 可核对的结果 |
| --- | --- | --- |
| 平台 · 条款库与模板 | 平台管理员登记条款的类型、作用范围、单位、继承方向、执行点和可调边界。以试用、团队、企业、合规、开发者五类模板起草、校验、发布新版本 | 已发布版本可回查。模板换版后，存量合约继续引用签发时的版本 |
| 平台 · 租户合约台账 | 按租户查当前合约，钻取后选择模板版本，填写席位和获准模型，按权限登记协议价及例外。签发或变更前预览席位缺口、失效选择、受影响的成员和设备 | 每次签发生成带生效时间的合约修订，保留上版、经办人及变更原因。平台录入的商业例外须符合条款库边界 |
| 租户 · 我的合约与配置 | 户主在“我的合约”查看权益及模板版本；在“租户配置”编辑开放条款。每项并列显示签约范围、当前选择、实际生效值和限制来源。恢复继承、预览、发布为独立动作 | 配置获得独立修订号。越界时指出字段、请求值和当前上限，整次保存失败。户主可选择目标模板并提交升级意向，扩权或改价由平台签发后生效 |
| 租户 · 分组与成员 | 复用分组和成员详情。分配开关开启时，在管理者原有权限内设置该级条款；展示上级限制，以及本月已用、预留和剩余 | 调整归属或配额后，能看到哪一级限制了该成员。关闭分配时，相关配置按当前合约失效，页面解释原因 |
| 生效预览与审计 | 按权限选择成员、系统和架构，查看其 Agent、发行、模型、费率及不可用原因；从变更记录查看两层修订、前后值、影响范围和设备下发状态 | 预览与 Server、Edge 使用同一套有效值。可区分平台未授权、租户关闭、设备无兼容发行、Provider 或费率不可用 |

平台操作使用独立的平台管理员身份及全局会话。租户域建议沿用现有分工：户主发布租户级配置且独占监察授权；管理员维护获准的组和普通成员配置；组管查看本组及子组的获准信息；成员查看自己的有效能力和用量。商业议价详情只向平台和本租户户主开放。管理端使用台账、钻取、页内表单，按钮依服务端返回的 `actions` 展示，写入时由服务端再次校验身份、租户和条款。[角色与操作契约](../../contracts/http-api.md) · [监察与配额约束](../../contracts/data-model.md)

## 3. 有效配置怎样计算

1. **先确定授权。** 读取该租户已生效的平台合约及其固定的模板版本。目录停用的模型、Provider 或发行从实际可用项中剔除。模板更新本身不会扩大已签权益。
2. **再逐层收窄。** 顺序为租户配置、从根到所在组的各级配置、成员配置；条款只在登记的作用域出现。允许列表取交集，数值上限取最小值，布尔开关逐层相与。条款缺省表示继承，显式空允许列表表示全部关闭。配额为零表示耗尽，配额为 `null` 表示本级不另设上限。清除本级设置后重新继承上级。
3. **分清固定值与最低要求。** 签约席位、议价等平台专属值在租户端只读；治理下限按条款指定方向合并，例如至少保留 90 天取各级下限的最大值。如果同时设有最长留存期，发布前检验上下限有交集。展示倍率由价格派生，席位数只控制人数。
4. **把成员权限和共享用量分别核算。** 发布时计算成员有效能力；签发或续租时实时检查余额、本人及每一级祖先组的剩余配额。一个组的 100 块橡皮由整棵子树共享，两名成员合计最多使用 100 块。活跃租约预留计入已占用额，历史结算按原记录保留。[配额及租约口径](../../contracts/data-model.md)
5. **再匹配设备。** 模型还需有兼容路由和生效费率，发行需匹配设备且可获取。Edge 只接收有效路由所需的密钥信封，管理端预览和审计均不展示密钥。低余额兜底也只能从该成员已启用、协议兼容的模型中选择；候选为空时告知原因并停止新请求。[Edge 下发契约](../../contracts/edge-ws.md)

例如平台授权 A、B，租户启用 A、B，研发组只开放 B，则组内成员实际最多能用 B。组员请求启用 A 时，页面指出限制来自研发组。若 B 的 Provider 停用，预览显示“B 暂无可用上游”，设备没有可用模型。平台恢复上游后，仍按当时有效的租户和组配置计算。

## 4. 发布、变更与设备生效

- **签发与配置发布。** 草稿可反复编辑，预览不产生业务效果。提交时复核目标合约、租户配置的当前修订、操作者和边界。任一版本过期时，保留草稿并提示重新预览。同一发布重试只产生一版和一条变更记录；有效值、热路径字段、审计与待下发记录须对应同一次成功发布。
- **合同收紧。** 平台撤销模型 B 时，新的有效集合立即剔除 B。历史选择保留可查，当前配置标记“授权已收回”。建议显式选择被撤销后，即使平台重新授予 B，也由户主确认再启用；采用“继承”的配置随上级生效。平台下调席位时，若已有 45 名活跃成员、合约降为 40 席，建议保留已激活成员，显示超额 5 人；降到 39 人后才可再开一席。按新上限检查新增、重新启用和接受邀请三个入口。
- **服务端与设备的时差。** 合约生效后，Server 的管理操作和新租约使用新边界；已签发租约依现行规则结清。在线 Edge 应用新配置后停止向已撤销路由发起新请求，离线设备受原租约到期约束，重连时拉取最新配置。页面分别显示业务生效版本、设备目标版本和可证实的应用状态。逐设备确认能力上线前，显示“待确认”；连接在线或已发送均不足以证明设备已应用。[设备确认与路由计划](../plan/master-plan.md)
- **追溯与恢复。** 平台合约修订、租户配置修订和设备下发序号分别记录。恢复某版租户配置时，按现行合约重新预览并生成新修订。需恢复已收回权益时，由平台另行签发；历史用量关联发生时的有效费率与相关修订。

## 5. 存量切换与验收

旧合约只有一条修订历史，户主可以修改席位和模型。即使是初始修订，系统也会把户主记录为更新人。迁移时不能仅凭最新值、首版或更新人推定已购买权益。[初始合约写入](../../server/src/seed.ts)

建议按租户切换。先保留旧修订，列出当前席位、活跃人数、模型、发行钉、租约、可见性及组/成员配额。平台核对签约依据，确认该租户的平台合约；将原有使用选择映射为租户配置。缺少依据的租户标记“待平台核对”。过渡期冻结旧入口对权益的扩张。切换前并列预览旧、新两套结果，逐项确认有意收紧的差异。切换后兼容读取由有效值派生；旧整单写入应提示改用新入口。回退仍以最近核准的平台边界为准。

| 审定后用于验收的场景 | 预期结果 |
| --- | --- |
| 平台签 50 席及 A、B；户主提交 51 席或模型 C，包括经旧写入口提交 | 拒绝整个变更，两层修订和设备目标配置都不变；户主可单独保存“只启用 A” |
| 只剩 1 席时，同时接受两个邀请 | 只有一个成员新增成功；拒绝的一方不消耗邀请次数。直接新增和重新启用同样受限 |
| 平台从租户合约撤掉 B，同时户主发布仍含 B 的旧草稿 | 提示版本冲突或越界；新的预览、路由、费率和 Provider 密钥范围均与最新授权一致 |
| 研发组共享月配额 100 块，已结算 80.125 块、活跃租约预留 15 块 | 全组最多再预留 4.875 块，还受本人配额、余额及租约上限约束 |
| 将租约额度设为 2.5 块，账本有一笔费用为 1 毫橡皮 | 保存后回显 2.5 块，协议字段为 2500；流水显示 0.001 块。输入 0.0005 块时提示精度，保留原值 |
| 平台发布模板新版；租户未升级；另有设备离线 | 租户仍使用已签版本；租户后续升级可追溯；离线设备显示待确认，重连后按最新有效配置恢复 |
| 存量租户旧记录有模型 C，但平台只能核准 A、B | 列出授权差异及受影响成员，平台确认后切换；旧客户端或配置回退均不能重新授予 C |

## 6. 请审定的决定

| 决定 | 本稿建议 |
| --- | --- |
| 签发权与席位 | 户主可选模板、提交升级意向；新增授权或改价须平台签发。首期只设签约席位上限，降到现有人数以下时阻止新增和重新启用，由户主安排减员 |
| 自助配置范围 | 户主可选授权范围内的模型、Agent 和可调条款。管理员沿用现有组和成员管理范围，组管首期只读。撤权后重新授予，显式选择由户主确认恢复 |
| 首期交付边界 | 首期打通模板版本、签发、租户配置、有效值、审计、迁移和现有席位／模型／Agent／租约／监察／组员配额执行点。自有上游、主备路由、限速、低余额兜底、按次工具费及折扣月结按依赖再启用。界面只开放已有执行点的条款 |
| 收费范围 | 建议以原稿 §9 的模型用量和付费外部工具为计量范围，统一后文出现的存储、Agent 启动收费示例。模板配额、价格及告警阈值示例仍待确认 |
