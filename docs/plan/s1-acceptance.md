# S1 全程验收清单

## Server 与管理端

本章是**待执行清单**，不是通过报告。编号对应 [S1 七条标准](sprint-1.md#s1-验收标准)；接口、序号、账务和错误判据见 [contracts](../../contracts/README.md)，故障对照来自 [SIMA 教训](../specs/sima-lessons.md)。范围冲突时按 [总体计划 §7 用户裁决](master-plan.md) 执行：S1 包括 Anthropic → OpenAI Chat，不只验同协议透传。

**共用夹具与记录法。** 用隔离的测试租户 A/B（同显示名、不同 ID）、合成对话、已知倍率、平台管理员及不同租户角色；用实际 Server/Web，关闭管理端 mock。上游用可记录请求数和用量的假服务。记录提交号、`/v1/healthz`、环境、浏览器版本和数据集；每项记 `通过 / 不通过 / 无法验证`，附证据路径、失败最短复现或缺失条件。对时后用 `device_id / session_id / request_id / lease_id / seq` 串起证据；不保存验证码、明文密钥、令牌、预签名 URL 或真实对话。真机安装与两小时真实运行由总督安排；模拟与压缩时钟不能替代签收。

### 1. 新员工五分钟内装好并登录（S1-S1、W1）

- **前置：** 干净 Mac；A 有空席位、有效邀请码；另备已加入 A/B 的成员和已满员租户。租户选择器使用稳定 ID 而非名称。
- **操作：** 从开始安装计时，分别走已有成员验证码登录、新员工验证码＋邀请码入租；选 A，查 `/v1/me`，注册设备并取 WS `welcome`。再试仅邀请码、过期码、非成员选租户；在仅余一席时用两名新员工同时接受邀请。
- **期望：** 五分钟内进入可工作的 Desktop；验证码是认证必要条件，邀请码只管加入；`me` 与 `welcome` 的用户、租户、设备相符。非成员不可选入，最后一席只成功一人，失败者不消耗邀请次数、不产生成员或设备；B 不变。
- **证据：** 安装开始/登录完成时间，脱敏的登录→选租户→设备注册状态码，`me/welcome` ID，对照租户成员数、席位、邀请使用次数。只有 API 证据时，五分钟整链标无法验证。

### 2. 启动获准 Agent，模型流量不经 Server（S1-S1、S3、W2）

- **前置：** 合约只允许指定 Agent、模型和 Provider；备有发行版本、架构、大小及 SHA-256，已注册带公钥的设备、另一个未获准的 Provider 和本地假上游。
- **操作：** 启动时关联 HTTP 发行信息、WS `config/secret/lease` 与假上游首个请求；对 Anthropic 透传与 OpenAI Chat 路由各做一次。检查合约不允许的模型、无公钥设备的下发结果。在两个合法连接入口切换；模拟同步未完成时登出、换号、换后台和同一登录鉴权被拒。
- **期望：** 仅获准发行项可启动，版本/校验与发行目录一致；模型内容只走本机 router → 假上游，不由 Server 中继。密钥按设备和获准 Provider 加密；无公钥不发 secret，页面/API 不返回可读密钥。入口改变不混淆租户或上游身份；旧响应不能覆盖新配置，真实鉴权错误不显示成普通离线。
- **证据：** 发行元信息、配置 revision、下发的 Provider ID 和帧类型（不存 secret 内容），启动/假上游计数与 Server 路由记录，错误分类与变更前后当前账户/租户 ID；下载校验和进程侧证据与 Edge 同一次启动关联。

### 3. 连续两小时、控制链路断两分钟后回流完整（S1-S2、S4）

- **前置：** 会话跨多个租期，余额充足；断开前剩余租期 >2 分钟，预算足够；准备含工具回合、起止事件及 usage 的已编号夹具。先压缩时钟演练，再由总督安排两小时真机记录。
- **操作：** 持续多轮工作，仅断 Edge↔Server 120 秒（保留本机→假上游）；恢复后从 `welcome.ack_seq+1` 补传。另测丢 ACK 后重发、乱序（先 N+2，后 N+1，混合 events/usage）、提交前写入失败、提交后 Server 重启，再握手核对游标。单独注入仅上游断流、短租约连续两次暂不可达后及时恢复/过期后才恢复。
- **期望：** 控制面中断期间有效租约内会话继续，无重新登录或模型请求重放；网络全断时不声称可访问远程上游。ACK 只确认**已提交且连续**的每设备公用序号，不跳洞；重启仍能读回，重发不增加事件、费用或流水。限期内可续，过期即停，不靠换租户/模型/上游续租；上游断流、鉴权拒绝、租期结束、前台断开分别可辨。
- **证据：** 两小时首末与中间活动时间、断开/恢复时间、心跳与会话身份、补传前后 ACK、按设备排序的持久化 seq/种类/计数和假上游请求数；逐项对照原始夹具，不能只看总条数。另附压缩测试与真机记录，区分结论。

### 4. 管理员五秒内看到完整对话与费用（S1-S4、S6、W4）

- **前置：** 同步时间；打开实际人员→会话→阅读页，订阅 `/v1/observe/stream`。夹具含多轮文本、工具调用与结果、四类 token；另准备坏行、超长工具结果、无尾帧和租户 B 的会话。
- **操作：** 在线逐条记录源事件产生时间与浏览器首次显示时间（含 usage 出现/费用更新），不手动刷新。对照 `/observe/sessions/:id/events?after_seq=`、usage 和源记录；中途重连 SSE。另以允许/不允许查看的身份分别读详情和订阅，核对 `/audit`。
- **期望：** 在线每个样本端到端 ≤5 s（不以平均值或 SSE 到达代替可见时间）。正文按序、仅新增一次，工具回合可关联；坏行有醒目 `gap`，截断明确标识，thinking、签名、凭据不可见。四类 token 按有效倍率独立折算，与整数毫橡皮、会话汇总一致；`complete=false` 标待结算，不伪装成零或已结。SSE 断线恢复后无遗漏，人员、摘要、详情均不越权；每次读取对话事件可查操作者、对象和时间。
- **证据：** 源 seq→数据库→页面的对照表，各样本时间差及最大值、逐项算费算式、页面截图、审计行、B 侧查询结果。离线补传耗时另列，不混入在线 5 s 样本。

### 5. 余额用完，下一次请求立即被拒（S1-S2、S6、W3）

- **前置：** 空账租户、两台设备、固定倍率；配置一个正好耗尽预算的请求。平台全局令牌用 `/v1/platform/ledger/topup` 充值，重放同一 `Idempotency-Key`。记录 `/balance`、`/ledger` 的初值。
- **操作：** 两台设备同时领租约；在隔离算例中使唯一未结租约预留 1000 毫橡皮、实际用 300，以累计 `used_milli=300`、同一 `op_id` 续约两次并重传 usage。另跑耗尽用例，把其余租约结清，观察 cutoff 与下一次请求；另留一个过期租约离线超过 24 小时。用租户角色试平台充值；查充值与合约修改审计。
- **期望：** 不超额预留。算例旧租约只结算 300、释放剩余 700；有新租约时单列其预留。任一时点可用余额＝充值＋调整－已结消耗－未结预留；usage 回流不是第二次扣款，缺 lease_id 待核对。过期离线不能自动释放，超 24 小时监察可见。确认余额和可用租约额度都耗尽后，下一请求本机立即拒绝（`balance_exhausted`、中文处理方法），假上游计数不增加；区别于 `lease_expired`。租户角色不能用平台充值，合法充值/改合约留审计。
- **证据：** 每步余额/预留/流水/租约快照、幂等重放前后差值、WS cutoff 与客户端错误、假上游计数、监察及审计；全部金额以毫橡皮列示。

### 6. Agent 仅靠 Server API 拉取指定设备日志（S1-S5、W5）

- **前置：** 两租户各一台测试设备；A 日志含唯一非敏感标记，假造的敏感测试串不得出现在诊断输出。RustFS 可用，准备 owner、admin、平台管理员及无权角色。
- **操作：** 用 HTTP 客户端按 `/v1/openapi.json` 找 API，无需打开网页：`POST /v1/devices/:id/diag {kind:"logs"}` → 关联 WS `diag`、上传和 `diag_result` → `GET /v1/diag/:id` → 实际下载并打开包。各授权角色单独测试；换普通成员/B 租户，再于十分钟内对同设备新建第二任务。另测设备离线/上传失败及七天保留届满。
- **期望：** 成功包能解开且只有目标设备标记，不含令牌、凭据、对话正文；设备页状态对应同一 diag_id。越权不能建任务、读结果或取得链接；限频为每台设备每十分钟最多一次（429），失败不显示可下载的成功包；发起动作写审计，七天保留届满对象不可再下载（短期签名失效不等于对象已清理）。
- **证据：** 脱敏 API/WS 时间线、下载状态/大小/包摘要、解包标记与敏感串检查、拒绝状态及无任务增量、审计和对象存储生命周期/到期实测；未验证到期删除时单列缺证。

### 7. SIMA 三种页面、服务端分页与两种视口（S1-W1～W5）

- **前置：** 实际 Server 中造超过两页的成员、多个 Provider/模型及会话，含长名称和长工具输出；浏览器 100% 缩放，分别设 CSS 视口 1280×720、1440×900。
- **操作：** 每种尺寸执行：成员台账查询/筛选→第二页→选中→详情→返回；Provider→模型→倍率、人员→会话→对话连续钻取；展开成员/合约/充值表单，切 Tab、保存、取消；用旧 revision 再保存。检查设备/诊断页；以不同角色及空列表重走操作入口。翻页时记录网络请求、`items/total/next_cursor`；量取根容器 scroll/client 宽高、行高，滚动内容区。
- **期望：** 工具栏一行、行高 32–40 px、分页固定、仅内容区滚动；钻取台账向左缩，右侧详情可继续钻，返回保留查询、页码、选中和滚动位置。查看/编辑同布局、新建为空，在右侧展开，不用弹窗/遮罩/抽屉；长表单用 Tab 或互斥折叠。服务端分页及过滤，Provider/模型过滤后的 total 与游标不混入其他对象；无前端全量截页。按钮来自对象、列表或 `/me.actions`，API 自身也拒绝无权操作；旧 revision 返回 409 不覆盖新值。两种视口根宽高均无外层溢出，内容和按钮仍可达，不能用裁切冒充通过。
- **证据：** 两种尺寸下的台账、深层钻取、长表单截图；逐页的根尺寸/行高/滚动容器实测；分页及返回前后状态、actions 与可见按钮对照、冲突响应和保存后回读。mock 截图只作布局证据，不签收联调。
